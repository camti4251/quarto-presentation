Introduction

Why does documentation matter?

We also need to explain:

  • What we did
  • Why we did it
  • How we got the results

Code and explanations should be easy to follow.

Hello everyone. Today I want to talk about literate programming and how we can use Quarto.

When we work with data, it is not enough to calculate a result. We should also explain how we got it. This is important because other people may want to understand or check our work.

The problem

Code and explanations are often separated

Imagine working on a data analysis.

  • You write your code in RStudio.
  • You get some results.
  • You copy the results into a Word document.
  • You write your explanation separately.

If you change the code later, you may also have to update the results in your document.

This can make the process confusing and time-consuming (Rodrigues, 2023).

Think about a normal data analysis project. We often have one file for the code and another file for the report.

The problem is that the results in the report do not always change automatically when we update the code. This is one reason why combining code and explanations can be useful.

What is Literate Programming?

Literate programming combines:

  • Programming code
  • Explanatory text
  • Results of the code

The code tells the computer what to do.

The text helps people understand what is happening.

The main idea is to make code easier to read and understand (Knuth, 1984; Rodrigues, 2023).

Literate programming is not just about writing code. It is also about explaining the code.

The computer needs instructions, but people need explanations. With literate programming, both are part of the same document.

Donald Knuth introduced the concept in 1984.

Why is reproducibility important?

In research and data analysis, other people should be able to follow the work.

This means they should be able to understand:

  • Which data were used
  • Which steps were taken
  • Which code was used
  • How the results were produced

Good documentation makes an analysis easier to check and repeat (Rodrigues, 2023; The Carpentries, 2025).

Reproducibility is an important part of data analysis.

For example, if another student wants to understand my results, they should be able to see what I did and which code I used.

This does not mean that every analysis will automatically give the same result in every situation. The data, software and working environment also matter.

What is Quarto?

Quarto is an open source publishing system.

It allows us to combine:

  • Normal text
  • Programming code
  • Results and visualisations

We can use it to create documents and presentations in formats such as HTML and PDF.

It works with languages such as R and Python (Quarto Development Team, n.d.; The Carpentries, 2025).

Quarto is a tool that helps us put this idea into practice.

We can write normal text, add code and show the results in one document. Quarto can then turn this document into different formats.

For example, we can create an HTML document or a PDF.

How does a Quarto document work?

A Quarto document usually contains three main parts.

Part What does it do?
YAML Contains document settings
Markdown Contains text and headings
Code chunks Contain executable code

The file has the extension .qmd.

(The Carpentries, 2025)

A Quarto document is saved as a QMD file.

There are three important parts. YAML is at the top and contains settings like the title and author. Markdown is used for normal text and headings. Code chunks contain code that Quarto can execute.

What are code chunks?

Code chunks are sections in a Quarto document where we can write and execute code.

For example:


::: {.cell}
::: {.cell-output .cell-output-stdout}

```
[1] 4
```


:::
:::

We can also control how the code is displayed.

  • echo: true shows the code.
  • echo: false hides the code.
  • eval: false prevents the code from running.

(The Carpentries, 2025)

Code chunks are an important part of Quarto.

They allow us to include R code directly in the document. We can decide if the code should be visible or hidden.

For a presentation, showing the code can be useful because the audience can see how the result was calculated.

What happens when we render?

The .qmd file is the source document.

When we render it, Quarto processes the text and executes the code chunks.

The result can be an HTML document or another supported output format.

This means that the text, code and results stay connected (Quarto Development Team, n.d.).

Rendering means creating the final document from the QMD file.

Quarto reads the document, processes the text and runs the code chunks. It then creates the output.

This is useful because we do not have to copy every result manually into another document.

Advantages and limitations

Advantages Limitations
Text and code in one place Some technical knowledge is needed
Results can be updated Code errors can stop rendering
Easier to follow the analysis Software and packages are required
Different output formats Initial setup takes time

Quarto supports reproducible work, but it does not guarantee reproducibility by itself.

(Rodrigues, 2023; The Carpentries, 2025)

In my opinion, one of the biggest advantages is that everything is in one place.

It is easier to understand what the code does and how the results were produced.

However, Quarto also has limitations. Users need to understand some basic programming concepts. If the code contains an error, rendering may fail.

Conclusion

Literate programming connects code with explanations.

Quarto makes it possible to put text, code and results into one document.

This can help us:

  • Understand data analysis more easily
  • Document our work
  • Update results
  • Share our analysis with others
